================================================================================
TUNING NOTES
================================================================================

_no_los_timer / NO_LOS_PATIENCE
  Currently 2.5s — fires too aggressively on soldiers that are just
  waiting for a shot window. Recommend bumping to 4.0-5.0s so soldiers
  hold position a bit longer before repositioning. Edit in enemy.gd:
    const NO_LOS_PATIENCE: float = 4.0

advance_distance
  Controls how far each ADVANCE step moves. Currently 3.0m. For longer
  range firefights bump to 5.0-6.0. Per enemy type via inspector or
  EnemyProfile resource when that's implemented.

cover_search_radius (soldier.gd)
  25m radius for cover seeking. If cover points are sparse, increase.
  If soldiers are grabbing cover too far away, decrease.

suppress_duration (soldier.gd)
  3.0s default. Increase for heavier suppression feel.

combat_recon_time (enemy.gd export)
  1.65s default. Lower = more aggressive re-evaluation.
  Tune per enemy type: grunt 1.65, heavy 2.5, sniper 3.0.


================================================================================
ROADMAP
================================================================================
work through these in order. each section is a session or two.


--------------------------------------------------------------------------------
PHASE 1 — FINISH AND TUNE WHAT EXISTS [1-2 sessions]
--------------------------------------------------------------------------------
before adding anything new, get what's built working well in the arena.

- tune NO_LOS_PATIENCE from 2.5s to 4.0-5.0s [too aggressive currently]
- wire grenade .tscn in editor [projectile scene, explosion scene, indicator]
- test and tune grenade throw arc [fuse_time, throw_speed, min/max distance]
- commit soldier reload cover behavior + squad notify_suppressor_reloading
- wire stimulus manager to player weapon [GUNSHOT_HEARD from player fire]
- fix formation stacking [soldiers spread into a loose line on advance]
  - simplest: offset each member by slot index along perpendicular axis
- test DEFEND in arena [set one squad to DEFEND, other to ADVANCE]
  - do defenders spread out properly? do they hold position under fire?
- add break contact [squad withdraws if >50% casualties]
  - squad._tick_engaged: if living < total * 0.5, set_objective(WITHDRAW, spawn)


--------------------------------------------------------------------------------
PHASE 2 — CONTACT RANGE POSTURE [1-2 sessions]
--------------------------------------------------------------------------------
squads react differently based on how far away contact is.

- add contact_range measurement when _on_combat_triggered fires
- add EngagementPosture enum [IMMEDIATE_ACTION, FIRE_AND_MOVEMENT, FIRE_BASE]
- IMMEDIATE_ACTION (<15m): everyone engages from current position, no bounding
- FIRE_AND_MOVEMENT (15-40m): current system, suppressor/advancer bounding
- FIRE_BASE (>40m): all suppress first, advance only after N seconds of fire
- update assign_roles() to branch on posture
- this fixes the "enemy runs straight at you from 60m" problem


--------------------------------------------------------------------------------
PHASE 3 — STRATEGIC OBJECTIVES + GAMEMASTER [2-3 sessions]
--------------------------------------------------------------------------------
command layer that drives squads at the mission level.

- build GameMaster node [world child, holds all squad + objective refs]
- ADVANCE_AND_HOLD [advance to objective, switch to DEFEND on arrival]
  - squad._tick_unengaged: if at objective, call set_objective(DEFEND)
- HUNTER_KILLER [patrol toward last known enemy squad position]
  - needs squad-to-squad awareness: ai_manager tracks squad positions
- DESTROY_OBJECTIVE [advance to target, interact on arrival]
  - objective node has health / apply_damage method
- wire GameMaster to arena [give each squad a strategic order on load]
- this is where the game starts feeling like a real scenario


--------------------------------------------------------------------------------
PHASE 4 — PLAYER SQUAD [1-2 sessions]
--------------------------------------------------------------------------------
give the player something to command.

- player squad [Squad node, faction ALLIED, player as squad leader]
- command system [already partially built in test_character.gd]
  - raycast to world → squad.set_objective(ADVANCE, hit_position)
  - hold key to cycle objective type [advance / defend / withdraw]
- HUD squad status panel [health bar per member, state indicator]
- squad follows player loosely when no objective set
- player squad persists between bonfires [reset health, not position]


--------------------------------------------------------------------------------
PHASE 5 — SPECIALIST CLASSES [2-3 sessions]
--------------------------------------------------------------------------------
once the base soldier works well, add specialist types.

- NCO [extends Soldier, overwatches, directs roles, calls retreat at 50% loss]
- HEAVY / MG [extends Soldier, always SUPPRESSOR, high mag, slow move]
  - fire_base posture: MG establishes position, others advance under cover
- DRONE [extends Enemy, no navmesh, Vector3 steering, uses drone_bomb]
  - hovers at altitude, strafes, retreats when hit, can be spawned by squad
- ENGINEER [extends Soldier, fortifies position, deploys turret/drone]


--------------------------------------------------------------------------------
PHASE 6 — MISSION STRUCTURE [2-3 sessions]
--------------------------------------------------------------------------------
build the loop around the AI.

- GameMaster assigns mission to player on level load
  - ELIMINATE enemy squad
  - HOLD position for N seconds
  - ADVANCE with squad to objective
- mission progress UI [objective marker, timer if applicable]
- mission complete → level exit or next wave
- mission fail → respawn at bonfire, enemies reset
- build arena into first proper mission
  - enemy squad advances to player side with ADVANCE_AND_HOLD
  - player must stop them with their allied squad


--------------------------------------------------------------------------------
PHASE 7 — POLISH AND FEEL [ongoing, do alongside other phases]
--------------------------------------------------------------------------------

- NO_LOS repositioning: add a brief pause/crouch animation before moving
  so it looks like a decision rather than a spasm
- suppression effect [near-miss camera shake, screen distortion]
- bark / voice lines [state-aware: contact, suppressed, flanking, dying]
- stagger on heavy damage [slow + accuracy penalty for 1-2s]
- grenade variety [smoke, EMP — extend AIEquipment, easy to add]
- flocking / separation [soldiers don't stack on same navmesh point]
- signal / e-warfare system [designed in design doc, build after phase 5]
- threat zones [designer-placed, squad slows and spreads approaching]
- weapon variety [rifle, MG, rocket — configure via AIWeapon exports]


================================================================================
ARCHITECTURE NOTES FOR REFERENCE
================================================================================

CLASS HIERARCHY
  AI → Enemy → Soldier → [NCO, Heavy, Engineer]
             → [Drone - no navmesh, Vector3 steering]

KEY RESPONSIBILITIES
  GameMaster      - strategic objectives, mission state, spawn waves
  Squad           - tactical decisions, role assignment, posture, formation
  Soldier         - individual behaviors, cover, suppress, bound, reload
  Enemy           - physics, nav, weapons, detection, stimulus, equipment
  AIManager       - registry, faction queries, shared data across squads
  StimulusManager - event bus, broadcasts stimuli to nearby AI

KEY VARS TO KNOW
  enemy.always_active       - bypasses passive mode distance check
  enemy._no_los_timer       - time without LOS, triggers _seek_los_position
  soldier.defensive_mode    - blocks advance/chase, holds position
  squad.default_objective   - ADVANCE or DEFEND, set in inspector
  squad.context             - UNENGAGED / ENGAGED
  squad.objective           - NONE / ADVANCE / DEFEND / WITHDRAW

ADDING A NEW ENEMY TYPE
  1. extend Soldier (infantry) or Enemy (non-infantry / drone)
  2. set faction, DefaultAIState, AllowedMovementOptions in inspector
  3. configure weapon scene [damage, fire_cooldown, magazine_size]
  4. add AIEquipmentSlot resources for any equipment
  5. add to squad.squad_members array
  6. add to "enemies" group for AIManager registration

ADDING A NEW EQUIPMENT TYPE
  1. extend AIEquipment
  2. override can_use(context) → return true when conditions are right
  3. override execute(context) → do the thing
  4. create .tscn, assign to AIEquipmentSlot.equipment_scene

ADDING A NEW MAP
  1. build in trenchbroom, import via funcgodot
  2. bake navmesh on NavigationRegion3D
  3. run CoverPointSpawner [assign nav region, generate]
  4. place SquadObjectivePoints
  5. place Squads with members and default_objective set
  6. wire GameMaster with squad and objective refs
